# LifeCycle frontend

## Тренировки (этап 5)

Защищённый маршрут `/workouts`: собственная библиотека упражнений, планы, активная сессия и история (по 50 результатов, с переходом к более ранним). `/workouts/session/:id` — выполнение или сохранённый результат. Ошибки API и пустые состояния отображаются явно. Используются существующие UI-компоненты, Markdown/приватная загрузка изображений и API; новых библиотек нет.

Упражнения поддерживают повторения, время и повторения × время, Markdown-технику, до трёх приватных иллюстраций и HTTP(S)-источники. Иллюстрации загружаются через Markdown-редактор. Конструктор задаёт круги, порядок, повторы, нагрузку и отдых; стрелки переставляют круги и упражнения. Одно упражнение можно включать несколько раз с разной нагрузкой. Прогрессия каждого включения задаёт исходный уровень, целевой уровень, начальную дату и количество календарных дней; расчёт линейный с округлением вниз на backend, допускается снижение. До 500 фактических шагов и суток расчётного времени; большие многократно повторяемые описания могут потребовать разделения плана (snapshot до 4 MiB).

В редакторе привычки можно выбрать план тренировки. Для разных занятий по дням недели используются отдельные недельные привычки. Подпривычки и тренировка в одной привычке несовместимы; редактор объясняет это и запрещает сохранение противоречивой формы. Кнопка «Открыть тренировку» в Today/календаре передаёт идентификатор плана и стабильный ключ даты появления.

Экран выполнения показывает текущий круг, повтор, упражнение, число повторений, технику/изображения/ссылки, таймер и фактическое число повторений. Для режима повторения × время таймер равен их произведению. Есть пауза/продолжение, подтверждение шага после серверного срока, явный пропуск и остановка с подтверждением. Истечение времени само не подтверждает выполненное упражнение. Безвременные повторения показывают прошедшее время. Сессия восстанавливается с сервера после reload, обновляется при фокусе и раз в 15 секунд; устаревшая команда требует обновления. Сервер отклоняет раннее завершение и повторное продвижение. Несохранённая заметка не отправляется с управляющими командами: используйте «Сохранить заметку тренировки».

Полное выполнение без пропущенных упражнений и с достижением повторений автоматически отмечает соответствующую привычку. Частичный результат, отмена, явная ручная отмена/пропуск привычки и изменение её правила/связи не подменяются выполнением; экран показывает факт `habit_completed`. Markdown-заметка сессии и результаты каждого шага доступны в истории. Начатые и завершённые сессии сохраняют снимок старых упражнений, плана и нагрузки после редактирования или удаления.

Перед удалением упражнения уберите его из активных планов; перед удалением плана отвяжите или удалите связанные привычки. Браузерные проверки этапа 5 покрывают мобильный конструктор на 390 px, приватное изображение, прогрессию, Today/календарь, паузу/reload, реальное истечение таймера, круги/отдых, остановку и сохранность исторического снимка после изменения упражнения.

React + TypeScript SPA, Vite, Tailwind CSS v4, Lucide. Локальные компоненты shadcn/ui располагаются в `src/components/ui`; конфигурация CLI — `components.json`. `@radix-ui/react-slot` обеспечивает композицию кнопок, `class-variance-authority` — типизированные варианты, `clsx` и `tailwind-merge` — согласованное объединение Tailwind-классов.

Требуются Node.js 22.12+ и pnpm 11.3.0.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Vite слушает порт 5173 и направляет `/api` на `http://127.0.0.1:8080`. Для локального Vite установите `APP_PUBLIC_URL=http://localhost:5173` в окружении backend: проверка Origin включает порт. В Podman Compose nginx обслуживает SPA на внутреннем порту 8080 и направляет `/api` в контейнер backend; публичный адрес по умолчанию — `http://localhost:8081`. Секретов, кодов и session token в localStorage нет. Сессия хранится в HttpOnly cookie, сохраняемые данные поступают с backend.

```sh
pnpm typecheck
pnpm lint
pnpm test
pnpm build
```

Маршруты: `/login` — вход или регистрация по email и одноразовому коду; `/today` — план дня; `/tasks` — задачи; `/calendar` — календарь; `/notes` — заметки и папки; `/countdowns` — обратные отсчёты; `/pomodoro` — таймер фокуса; `/profile` — необязательная типизированная анкета; `/settings` — предпочтения аккаунта; `/status` — публичная страница состояния. Главная страница после входа ведёт в Today; первое подтверждение email сохраняет переход к профилю. Защищённые страницы проверяют `/api/auth/me`. Выход отзывает серверную сессию. Срок кода — 10 минут; повторная отправка доступна через 60 секунд. Ограничения частоты и числа попыток дополнительно контролируются сервером.

Светлая, тёмная и системная темы применяются после сохранения и восстанавливаются с backend при следующем входе. Системная тема следует изменениям ОС. Все даты и предпочтения расписания сохраняются на сервере. Today и календарь используют часовой пояс и начало недели из настроек. Напоминания привычек появляются в открытом приложении после включения в настройках и в самой привычке.

`/status` вызывает реальный `GET /api/health/ready`. Успешный ответ 200 содержит `status: ready`, а ответ 503 — `status: unavailable`; `checks.postgres`, `checks.redis`, `checks.garage` принимают `ok` или `unavailable`. Проверка недоступного сервиса не подменяется успешным результатом. Запрос отменяется при размонтировании и ограничен 12 секундами.

Браузерные сквозные сценарии используют настоящие backend, PostgreSQL и Mailpit, без подмены маршрутов. Запустите Compose, затем:

```sh
pnpm exec playwright install chromium
pnpm test:e2e
```

`APP_URL` по умолчанию `http://localhost:8081`, `MAILPIT_URL` — `http://localhost:8025`. Тест входит по коду из Mailpit, сохраняет профиль, проверяет восстановление данных и темы после перезагрузки, затем выполняет выход.

Containerfile собирает production SPA и запускает nginx без root. HTTPS для публичного размещения должен завершаться на доверенном reverse proxy перед frontend.

## Основные данные (этап 3)

Заметки поддерживают папки, цвет, теги, поиск по заголовку и содержанию. Название папки ограничено 100 символами, название заметки — 200; теги — до 30 записей по 64 символа. Удаление папки оставляет заметки без папки; удаление безвозвратно удаляет заметку из БД. Markdown отображается в задачах и заметках с GFM (таблицы, списки, ссылки), без исполняемого HTML. Редактор загружает настоящие PNG/JPEG/WebP до 8 MiB через приватный API Garage; изображения доступны по сессии владельца.

Задачи доступны списком, Kanban и диаграммой Ганта. Редактор сохраняет Markdown, подзадачи, теги, цвет, приоритет, дедлайн и расписание. Today и календарь получают появления с backend; отметки повторяющейся задачи относятся к конкретной дате, а история сохраняет прежнее содержимое после редактирования или удаления шаблона. `TaskOccurrence.date` — дата в часовом поясе самого расписания и ключ отметки конкретного появления. Календарь группирует события с точным временем по `starts_at`, переведённому в часовой пояс профиля; события без времени используют дату появления.

Обратные отсчёты сохраняют категорию, значок, дату и ежегодное повторение. Следующая дата вычисляется сервером в часовом поясе аккаунта; 29 февраля в невисокосный год соответствует 28 февраля. Pomodoro использует длительности из настроек и серверные интервалы: запуск, пауза, продолжение, отмена и завершение после истечения времени. Связь с задачей добровольная; завершение таймера не выполняет задачу автоматически. Состояние восстанавливается после перезагрузки и обновляется при возвращении в окно.


## Привычки (этап 4)

`/habits` — создание, редактирование, поиск по тексту/тегу, удаление и история привычек. Используется общий редактор расписаний: один раз, каждый день, выбранные дни недели, каждые N дней, время/длительность и включительная дата окончания. Значок — пользовательский Unicode-символ. Описания привычки, подпривычек и отметок используют общий Markdown-редактор с приватными изображениями.

Подпривычки имеют стабильные UUID, собственные названия/описания и общее расписание родителя. Today и календарь показывают один родительский пункт с суммой выполнений N/M. Все подпривычки выполнены — родитель завершён. Можно явно пропустить или отменить появление; отметка и Markdown-заметка восстанавливаются после перезагрузки. Будущие и удалённые появления доступны для просмотра без изменения.

Правки применяются с сегодняшней даты в часовом поясе привычки. Прошлые версии правил и все сохранённые отметки, включая частичные, сохраняют исходные пункты и текст. Часовой пояс существующей привычки фиксирован для однозначности ключей дат. Историю можно явно корректировать до удаления; удалённые результаты доступны также из статистики.

Статистика за 1–366 дней показывает выполненные, явные пропуски, прошедшие без результата, отмены, ожидающие появления, суммы подпривычек, серии выполнения/пропусков и рейтинг привычек. В интерфейсе приведены правила расчёта. Все данные приходят с реального API.

Напоминания: включите общий переключатель в настройках и переключатель привычки, задайте время. Интервал берётся из привычки либо настроек. Проверка выполняется каждые 30 секунд, при фокусе и изменении привычки; подтверждение «Прочитано» сохраняется на сервере для этой даты. Окно напоминания — 24 часа после срока. Закрытый браузер не получает уведомлений; email/Web Push/звуковой канал в этот контракт не входят.

`pnpm test:e2e` включает сценарии привычек на мобильном экране, суммирования подпривычек, Markdown-отметок, календаря, истории после изменения/удаления и подтверждения напоминания после перезагрузки.

## Интимный журнал (этап 6)

Защищённый маршрут `/sex`, ссылка «Интимный журнал». Журнал использует действующую сессию, настройки часового пояса, общий API, UI и Markdown с приватными изображениями. Новых библиотек нет. Черновики и анкеты не пишутся в localStorage или URL; «Скрыть журнал» размонтирует содержимое/редакторы и отменяет запрос. Повторное открытие загружает данные с backend. Это скрытие экрана, не отдельная блокировка аккаунта.

«Новое событие» открывает добровольную анкету секса или мастурбации; обязательны только тип, местное время и IANA-зона (изначально из профиля). Длительность, число эякуляций, игрушки, смазка, обстановка, одежда, эмоции и желание повторить сохраняются отдельно; пустые измерения/ответы отличаются от нуля/«нет». Секс добавляет защиту, имя/пол партнёра, позы, несколько видов секса; мастурбация — источники порно и ощущения после. Смена типа требует подтверждения очистки специальных полей. Описания обстановки/ощущений отображаются Markdown; общая заметка использует существующий редактор с предпросмотром и приватными фотографиями.

Время события задаётся в явно указанной зоне, независимо от зоны браузера; повторяющийся час DST имеет выбор первого/второго вхождения, несуществующее время вызывает понятную ошибку. Будущее начало запрещено. Несколько событий за день, включая одинаковый момент, сохраняются независимо. Просмотр показывает все введённые сведения и исходную зону. Список и статистика используют текущую зону профиля.

Период от 1 до 366 дат и фильтр типа применяются одновременно к списку и статистике; список по 50 событий с переходами страниц, статистика по всему периоду. Показаны число записей/дней/типов, известная суммарная/средняя длительность, эякуляции с числом ответов, игрушки, эмоции и yes/no/unknown-ответы. Раскрываемая частота по дням сопровождается числовыми подписями. Дни без записей не означают воздержание; отсутствующие измерения не входят в среднее.

Коррекция/удаление явно пересчитывают статистику. Серверная revision защищает от перезаписи параллельных изменений; при конфликте черновик остаётся в форме, для дальнейшей правки откройте обновлённую запись из списка. Безвозвратное удаление требует подтверждения. Загруженные изображения остаются отдельными приватными медиа, в том числе при удалении анкеты. Журнал не попадает в задачи/календарь/общий поиск, общую ленту событий. AI получает только минимальную сводку при отдельном разрешении владельца. Область шифрования и открытые служебные метаданные описаны в backend/README.md.

Chromium-сценарии: мобильная полная анкета с фото/Markdown, два события в день, сохранение нуля/«нет», reload, коррекция/удаление и фильтр статистики, скрытие экрана, защита маршрута после logout, DST-ошибка/второе вхождение и защита от параллельной правки.


## Аналитика и удаление (этап 7)

`/analytics` — защищённая страница и пункт навигации. Диапазон 1–366 включительных дат, быстрый выбор 7/30/90/366 дней, явное применение собственных дат, обновление и скрытие содержимого экрана. Зона — из профиля. Пустые/ошибочные состояния и повтор запроса отображаются явно. После возврата фокуса разрешения и отчёт загружаются заново.

Карточки показывают реальные действия, активные дни, итоги ручных задач/привычек, подпривычки, до 10 лучших привычек и серии, подтверждённые тренировки/повторения и время Pomodoro. Интерактивный график переключает действия/задачи/привычки/тренировки, позволяет выбрать день и имеет числовую таблицу. Плановые минуты отличаются от фактического времени. Формулы процентов и правила отмен/ожидания объяснены рядом с показателями; null отображается как отсутствие данных.

Показатели профиля (только возраст/рост/вес) и интимная сводка (только количества/длительность) выключены по умолчанию и разрешаются раздельными явно подписанными переключателями. Пока разрешение сохраняется или перечитывается, отчёт скрыт; галочка отображает текущее действие сразу, при ошибке восстанавливается серверное состояние. Отзыв/новый диапазон/зона исключают показ старого отчёта, запросы отменяются при размонтировании. Источник прав — только сервер. Разрешения, отчёт и чувствительное содержимое не записываются в localStorage или внешнюю телеметрию. Разрешения этой страницы не предоставляют доступ AI.

Во всех прежних действиях архивации теперь кнопка «Удалить» и физический DELETE. Подтверждение объясняет сохранение истории и связи. Папка оставляет заметки без папки, родительская задача оставляет самостоятельные подзадачи; удаление используемого упражнения/связанного плана требует сначала убрать связь. Сохранённые результаты открываются из календаря и рейтинга и не редактируются. Заметка/отсчёт удаляются без скрытой копии в истории. Общие приватные изображения остаются самостоятельными медиа.

Проверка: `pnpm test:e2e`, включая мобильную аналитику на 390 px, реальные данные, opt-in/отзыв/reload, ошибки диапазона, график, ссылки на удалённые результаты, скрытие и logout; основные сценарии также проверяют подтверждение/отмену удаления заметки, папки, задачи, привычки и отсчёта.

## Финальная интеграция (этап 9)

В настройках доступны 12- и 24-часовой форматы времени. Today, календарь, история задач, подсказки Gantt, напоминания, журнал, аналитика и даты AI используют сохранённый формат; часы AI также используют зону профиля. Позиции Gantt рассчитываются из числовых минут, независимо от AM/PM. Формат нативных полей ввода определяется браузером; длительности таймеров не являются временем суток.

При возврате фокуса или видимости открытые ресурсы перечитываются с backend. Успешное обновление не снимает формы с экрана и сохраняет несохранённые черновики. Новая revision AI отменяет прежний предпросмотр и сохраняет черновик сообщения. Вход/выход сообщается другим вкладкам через BroadcastChannel без персональных данных и токенов; каждая вкладка повторно проверяет серверную сессию. При смене аккаунта прежнее дерево интерфейса и его приватные данные удаляются из памяти компонентов. При отсутствии BroadcastChannel повторная проверка сессии происходит при возврате в приложение.

`e2e/integration.spec.ts` проверяет редактирование между вкладками, выход/смену аккаунта, сохранность AI-черновика при смене прав, границу дня Tokyo → Los Angeles во всех представлениях расписания и задержанный настоящий ответ проверки сессии после logout. Устаревшие проверки отменяются при изменении сессии и не могут повторно открыть закрытый интерфейс.

## AI-помощник `/ai`

Главный экран — чат с перепиской и полем сообщения. «Отправить» автоматически создаёт новый чат при необходимости, готовит точный серверный запрос и отправляет его. Enter отправляет, Shift+Enter добавляет строку; ввод с IME не отправляется преждевременно. Ответ появляется автоматически, его можно скопировать; ожидающий запрос можно остановить. Новые ответы прокручиваются в видимую область, если пользователь не читает более раннюю переписку. Все шесть готовых запросов постоянно доступны над полем сообщения, в том числе после ответа и reload. Выбор добавляет текст к черновику, сохраняя уже набранное; период анализа остаётся доступным.

Точное тело запроса можно открыть через «Данные для отправки»; это необязательный шаг. Серверный preview действует пять минут и содержит модель, инструкции, ограничения выборки и до десяти успешных пар текущей revision. Автоматическая отправка использует тот же контракт preview/request_id. При неопределённом сетевом результате кнопка «Проверить отправку» проверяет тот же запрос без повторного inference. Незавершённый поток и ошибки провайдера показываются явно. Черновики сохраняются в памяти страницы отдельно для каждого чата, включая новый, и переживают обновление настроек.

Подключение, модель и разрешения открываются кнопкой «Настройки AI»; журнал предложений — «История изменений AI». Единая форма подключения доступна также в `/settings`. OpenAI API и OpenRouter используют отдельные ключи: password-поле очищается после сохранения, ключи/токены не возвращаются браузеру и не сохраняются в localStorage. При выборе другого способа сначала сохраните настройки. OpenRouter принимает ID модели вида `openai/gpt-4.1-mini` и использует ZDR/запрет сбора данных; доступность и цена определяются сервисом.

Для ChatGPT Login завершите официальный вход, загрузите модели, выберите модель, разрешите сообщения и сохраните. Сохранённый аккаунт можно выбрать, отключить, повторно авторизовать или полностью удалить с подтверждением. Оба API-ключа удаляются независимо от выбранного провайдера. Локальная отвязка сохраняет аккаунт LifeCycle и доменные данные; неподтверждённый удалённый отзыв отображается отдельно. Удаление чатов с подтверждением сохранено. Loopback OAuth требует браузер на том же компьютере и локальный HTTP localhost/127.0.0.1; с телефона/удалённого сервера используйте API-ключ.

### Какие записи видит AI

В списках `/notes` и `/workouts` у каждой заметки, упражнения и тренировки есть «AI Доступ». Старые и новые записи закрыты по умолчанию. Дополнительно включается соответствующее разрешение категории в настройках AI. Доступ к упражнению независим от планов: отмеченная библиотека передаётся даже без тренировок, а отметка плана не открывает закрытое упражнение. Результаты закрытых тренировок и связанные события/привычки не попадают в AI-контекст через аналитику. Обычная пользовательская аналитика не ограничивается этими отметками.

Переключатель сохраняется сразу, показывает ожидание и ошибку/откат при сбое, не перезагружает весь список. Сервер проверяет владельца и отдельную версию доступа; обычное редактирование содержимого не может выдать AI-права. Отзыв отменяет старые запросы/предложения и исключает прежнюю историю из новых отправок; сохранённая переписка остаётся доступной владельцу. Уже показанный точный предпросмотр устаревшей версии скрывается. Изменение доступа сохраняет черновик.

Форма «Цели и персонализация» и поле «Поиск в разрешённых задачах, заметках и тренировках» удалены. На странице `/workouts` есть отдельная форма «Цели и условия тренировок»: цели, оборудование, ограничения. Поля необязательны, до 2000 символов, сохраняются кнопкой «Сохранить цели и условия» и переживают reload. При конфликте другой вкладки текст остаётся в форме до явной загрузки сохранённых данных. AI получает эти сведения только при разрешении «Тренировки»; изменение условий делает прежние запросы и предложения устаревшими. Форма персонализации в AI не возвращается. Единое разрешение «Тренировки» управляет разрешённой библиотекой/результатами; для предложения записи также нужны «Предложения изменений AI» и отдельное подтверждение. Числовая аналитика, задачи, привычки, заметки, профиль и интимная сводка имеют независимые разрешения; согласие Analytics не предоставляет доступ AI.

### Просмотр и применение предложений

Ответ с поддерживаемым предложением показывает «Проверить изменения из ответа». Технический блок скрыт из обычного Markdown; сервер проверяет строгую схему и ничего не сохраняет до подтверждения. Просмотр содержит before/after, нагрузки и расписания. Предложение можно исправить обычными редакторами упражнения/тренировки/задачи/заметки. Далее нужно отметить «Я проверил все изменения» и подтвердить весь пакет. Задачи используют общие Today/календарь, заметки — безопасный GFM Markdown. AI не может менять доступ, удалять записи или обращаться к Contacts. Новые заметки/тренировки/упражнения тоже требуют отдельной отметки «AI Доступ» для следующего запроса.

Журнал переживает reload и отвязку AI. Undo требует подтверждения, доступен после отзыва AI-прав и сохраняет текущее состояние доступа к объекту; поздние правки/защищённые связи не перезаписываются. При известных медицинских ограничениях применение AI-нагрузки требует ручной проверки, обычный редактор остаётся доступным. Интенсивность необязательна и сохраняется в обычном плане/снимке выполнения.

`e2e/ai.spec.ts` проверяет мобильный чат на 390 px: отметки заметок/упражнений/планов и их сохранение, поля условий тренировок после reload и в точном запросе, одно нажатие для отправки, автоматический ответ, Enter/Shift+Enter, отзыв без потери черновика, удаление ключа и чата. `e2e/ai-upgrade.spec.ts` проверяет предложение → обычные редакторы → подтверждение → reload/undo → задачу в календаре и безопасный Markdown. Внешний ответ в этих тестах заменён явно синтетической зашифрованной fixture; нужны локальный Podman и `python3-cryptography`. Отдельная настоящая проверка ChatGPT Login через приложение завершилась успешно и дала четыре прошедших серверную проверку действия без применения к данным пользователя; результаты — в `project/project_progress.md`.

## Upgrade v1, этапы 1.4–1.5

`/notes`: фильтр «Доступ AI», подписи закрытых/разрешённых записей, выбор до 200 заметок и массовое разрешение/отзыв с отдельным подтверждением. При смене поиска/папки/статуса выбор сбрасывается; CAS-конфликт не применяет часть пакета. Новые заметки закрыты, дополнительно нужно разрешение категории Notes. Подсказка объясняет границы отзыва ранее переданных внешнему AI данных. Markdown/приватные изображения используют прежний общий редактор.

`/boards`: отдельный раздел досок, создание/переименование/удаление, URL `?board=<id>` для возврата после reload. Доска хранит собственные режим Kanban/Gantt и масштаб. Произвольные колонки имеют название и порядок. Карточки перетаскиваются между колонками и перед другой карточкой; стрелки и Select доступны для клавиатуры и мобильного экрана. Фильтры: текст, общий тег и статус. Добавление существующей задачи переносит её с прежней доски; новая задача создаётся тем же TaskEditor атомарно с членством. Снятие с доски/удаление доски сохраняет задачу. Для непустой колонки требуется выбрать получателя задач; отказ не закрывает форму. Колонки не меняют результаты повторений: статус меняется через задачу/Today/Calendar.

`/task-tags`: общая панель создания, переименования и удаления тегов. Переименование отражается во всех текущих задачах; удаление снимает связи с подтверждением. TaskEditor выбирает до 30 существующих тегов, ссылка открывает панель в другом окне; возврат фокуса обновляет реестр. Исторические snapshots сохраняют прежние имена. Теги заметок не изменены.

Gantt в `/tasks` и `/boards` использует минутные UTC-интервалы с отображением в зоне профиля, реальной длиной DST-дня, полосами через полночь и масштабами день/неделя/две недели. Перетаскивание переносит начало, левый/правый край меняет начало/конец при сохранении противоположного края. Нажатие полосы или Enter открывает точный ввод начала, окончания и длительности с взаимным пересчётом. Формат ввода datetime-local явно помечен зоной браузера, отображение графика — зоной профиля. Серия изменяется целиком с сохранением якоря и относительного сдвига правил; исторические завершённые/отклонённые полосы доступны только для чтения. Изменение защищено expected_updated_at, конфликт предлагает обновить задачи. Неопределённое время не выдаётся за точное; задача без расписания не имеет полосы. Изменения видны в Today/Calendar и обычном редакторе.

Chromium проверяет мобильные заметки/доски, подтверждение и reload, общие теги, безопасное удаление, фактические pointer drag/resize Gantt, точный ввод с переходом полуночи и сохранение индивидуального масштаба. Unit tests проверяют 23/25-часовые и пропущенные дни и границы изменения интервалов. Последующие этапы не реализованы.

## UX-правки задач, досок и навигации (31.10.2026)

Текущий рабочий экран заменяет прежние параллельные разделы задач и досок. В боковой навигации один пункт «Задачи», `/tasks` содержит общий список, задачи без доски и горизонтальную ленту пользовательских досок. `/boards` перенаправляет на `/tasks`, сохраняя query/deep links; старый TasksPage больше не содержит отдельной реализации списка/Kanban/Gantt. Kanban/Gantt выбираются только внутри конкретной доски. «Все задачи» и «Без доски» используют те же карточки и API, без отдельного представления или статусов.

Общий Shell занимает всю высоту экрана. Навигация закреплена слева; на узком экране остаётся компактная панель и разворачиваемое меню. Рабочая область справа использует оставшуюся ширину. Горизонтальная лента досок и Kanban-колонки прокручиваются независимо от страницы; колонки имеют собственную вертикальную прокрутку. Создание, переименование, порядок, перенос и безопасное удаление используют прежний CAS/API. Меню закрываются после выбора, по Escape и при клике вне меню.

Карточка показывает галочку выполнения, цветные теги и относительный срок («Завтра», «Через N дней», «Сегодня» в день начала или во время текущего интервала, включая переход полуночи). Колонка — этап работы, галочка — выполнение. Отдельного поля/фильтра доменных статусов в задачах нет. Исторические backend status и результаты сохраняются для совместимости и аналитики. Для повторов галочка относится к сегодняшнему доступному появлению; в календаре — к выбранному появлению. Переключение мгновенное, ошибка возвращает сохранённое состояние. Новый `/api/boards/memberships` объединяет задачи с именами доски/колонки, не копируя записи.

Панель `/task-tags` создаёт и меняет название/цвет (`#RRGGBB`) с палитрой и произвольным выбором. Цвет общий для всех досок, подписей Gantt, редактора и плана дня. Светлый/тёмный текст выбирается по яркости фона. Переименование обновляет связи, удаление сохраняет задачи. Изменение одного цвета не меняет версию содержимого задачи.

Gantt занимает доступную ширину и высоту рабочего экрана, имеет закреплённую колонку названий/галочек/тегов, горизонтальную и вертикальную прокрутку, переход по периодам, «Сегодня», масштаб и разворачивание почти на весь экран (Escape возвращает обычный режим). Полосы крупнее, drag/resize и точный ввод начала/конца/длительности сохранены. Завершённые snapshots остаются только для чтения; задачу можно снять с выполнения галочкой.

Выбор часового пояса находится только в настройках. Ввод Gantt/интервала задачи/интимного журнала и отображение используют настройку аккаунта, независимо от пояса браузера. ScheduleEditor проецирует старые правила в выбранный пояс и обратно, сохраняя их историю/исходные связи. Смена настройки не переписывает реальные моменты исторических событий; UI не показывает отдельные поля/подписи пояса. При повторе DST планирование выбирает первый момент, журнал сохраняет явный выбор первого/второго; пропущенное фактическое время отклоняется. Работающие заметки, их права AI и Markdown не перерабатывались.

Приёмка расширена реальными сценариями ленты/колонок, checkbox, цветов, большого/fullscreen Gantt и ввода по настройкам при другом поясе браузера. Снимки desktop/mobile создаются `tasks-upgrade.spec.ts`. `ui_upgrade_smoke.py` проверяет цвета/CAS/изоляцию/совместимость и memberships; включён в общую команду приёмки.

### Рабочее пространство — 02.11.2026

Заметки: «Новая заметка» открывает inline-название, Enter сохраняет приватную заметку. Название карточки открывает редактор справа; на узком экране редактор занимает экран. Содержание и характеристики разнесены по вкладкам. Папка, теги, цвет и галочка AI находятся в «Характеристиках»; AI-доступ сохраняется сразу отдельным API. Содержание сохраняется кнопкой, индикатор «Сохранено» появляется после ответа сервера. Закрытие или переключение с несохранённым черновиком требует подтверждения. Markdown/приватные изображения сохранены. Для AI-предложения тот же NoteEditor остаётся в окне обзора.

Выбор заметок хранит версии содержимого и AI-доступа. При выборе показываются перенос, добавление/удаление тегов, цвет, разрешение/отзыв AI и удаление. Изменение характеристик/удаление атомарно для всего набора; stale/foreign/invalid selection отклоняется целиком. AI продолжает использовать прежний независимый revision/confirmed-контракт. Фильтр сбрасывает выбор; можно выбрать до 200 показанных или снять выбор.

Все четыре существующих поиска используют FilterSearch. Свободный текст ищет по названию/содержимому, фильтры соединяются логическим И, минус исключает значение. Значения с пробелами заключаются в кавычки, русские/английские ключи равнозначны. Неизвестные ключи, неверные boolean/date и незавершённые значения дают подсказку; строка не исполняется как код. Значения тегов/папок сопоставляются без учёта регистра.

Подсказка рядом с полем перечисляет поддержанные фильтры и вставляет пример. Период статистики привычек также задаётся этой строкой, отдельные поля дат убраны; диапазон ограничен 366 днями. Фильтры работают с полными owned-коллекциями, старые server query API сохранены.

FeedbackProvider заменяет все прежние native JS confirm во frontend, включая старые маршруты. Очередь подтверждений использует оформленный Dialog/alertdialog с клавиатурой, Escape и отменой; удаление выделяется отдельно. Уведомления закрываются вручную/автоматически, повторы объединяются и располагаются выше нижних кнопок. При смене аккаунта/выходе очередь и уведомления сбрасываются, pending подтверждения отменяются. useAction сообщает об ошибках через тот же компонент и сохраняет сообщение в форме.

«Настроить панель» включает ручки drag и булавки, «Готово» завершает настройку. Незакреплённые разделы остаются в «Все разделы», настройка доступна даже при пустой панели. Есть порядок мышью/касанием и стрелками клавиатуры. На узком экране настройка разворачивает боковую панель. Порядок/pins сохраняются через owned `/api/navigation` с CAS; другие настройки аккаунта не сбрасывают навигацию.

На карточке задачи доски осталось одно троеточие: редактирование, отмена/возврат, история, снятие с доски, удаление. Результаты сортируются: просроченные → невыполненные → завершённые/отменённые, приоритет на порядок не влияет.


### Массовые заметки и навигация — 02.11.2026

`POST /api/notes/bulk`: `{items:[{id,updated_at}],action,folder_id?,tags?,color?,confirmed?}`. От 1 до 200 уникальных owned-заметок; `updated_at` — точная версия из GET. Действия `move|tags_add|tags_remove|color|delete`. Перенос допускает folder_id:null, color требует HEX, теги проходят общую валидацию. Для delete обязателен confirmed:true. Под owner lock все записи/версии/папка/результирующие теги проверяются до применения; stale → 409, чужая/пропавшая запись или папка → 404, invalid/duplicate/unconfirmed → 400, неверный Origin → 403. Изменения коммитятся одной транзакцией, возвращается `{affected:N}`. Название/содержимое/AI-доступ не изменяются действиями характеристик. Удаление использует прежний delete_note_in. Массовый AI-доступ остаётся на `/notes/ai-access` с независимыми revision/confirmed.

`GET /api/navigation` → `{ordering:string[],pinned:string[],revision}`. Ключи — 14 путей разделов shell. По умолчанию исходный порядок, все закреплены, revision:0. `PUT /api/navigation` принимает тот же объект: ordering обязан содержать весь каталог без повторов, pinned — уникальное подмножество (может быть пустым). Сервер проверяет revision под owner lock и возвращает увеличенную версию; stale → 409, неверный набор → 400. Владельцем всегда является текущая сессия. Миграция `0016_navigation_preferences.sql` добавляет отдельную таблицу с FK пользователя и JSONB-массивами; прежние settings/миграции/данные не переписываются. Сохранение settings не меняет навигацию.

`workspace_upgrade_smoke.py` включён в `acceptance.py --check-upgrade`: атомарность/владение/версии/CSRF заметок, сохранность текста и приватности, независимая навигация, валидация, CAS и конкурентные PUT.

### Upgrade 1.7: алгоритмы Pomodoro

`GET/POST /pomodoro/configs`, `PUT/DELETE /pomodoro/configs/{id}`: `{name,data:{work_seconds,chill_seconds,more_chill_seconds,sequence:[w,c,mc],repeat},revision}`; update/delete требуют текущую revision. До 60 интервалов, минимум один w, каждый тип 1–86400 секунд. Копирование — обычный POST нового объекта.

`POST /pomodoro/program {config_id,revision,task_id?}` фиксирует снимок. Прежний `GET /pomodoro` синхронизирует текущее время и возвращает session с `run_id`, `interval_index`, `interval_kind`, `program_name`, `program:{run_id,name,interval_index,sequence_length,cycle,next_kind,next_duration_seconds,repeat,revision,history_pending}`. Существующий `POST /pomodoro/{session}/{pause|resume|cancel|reset}` принимает опциональный `{revision}`; алгоритмы переходят автоматически, finish для них недоступен. Сброс сохраняет отменённый запуск и создаёт новый снимок. Старый work/break контракт сохранён.

`GET /pomodoro/history?offset=0` возвращает `{items,next_offset}` по 50 интервалов. Время считается от серверных сегментов, паузы исключаются. После длительного отсутствия часы восстанавливаются сразу, история — пакетами до 5000 на чтение; при ненулевом history_pending stop/reset вернут конфликт для повторного чтения, пока вся история не сохранена. Одинаковые run/index не дублируются. История остаётся после удаления конфигурации/задачи. Существующая аналитика синхронизирует историю и учитывает только completed Work.

### Upgrade 1.8: профиль и жизненная история

`GET /profile` возвращает прежние поля, `revision`, `origin`, `firsts`, `harmful_habits`. Origin: region/given_name/surname/patronymic/sex/childhood_languages/maternal_birth_order/multiple_birth_count; дата/страна рождения остаются прежними полями. Firsts: school_entry_year/school_graduation_year/education/profession/job/residence_country/foreign_language/achievement/completed_project. Harmful habits: `[{id,name,current:bool|null,ever:bool|null,periods:[{id,start_date:date|null,end_date:date|null,note}]}]`. До 30 привычек и 100 периодов каждой. Смена current не изменяет периоды автоматически; исторические факты и текущие характеристики независимы.

PUT принимает полный объект или частичный объект: пропущенные значения, в том числе внутри origin/firsts, сохраняются; null/пустая строка/пустой список очищают соответствующие поля. revision опциональна для старых клиентов и обязательна в новом UI; stale version → 409. Неизвестные поля, противоречивые статусы, дубли ID, будущие/перевёрнутые периоды, невозможные значения отклоняются атомарно. Даты используют день пояса аккаунта. Все личные поля остаются в AES-GCM encrypted_data; в миграции 0019 только счётчик версии. Явный AI profile permission охватывает полную анкету; изменение данных инвалидирует отправляемые старые previews, pending и контекст соответствующей revision. Ранее переданные провайдеру данные не удаляются очисткой поля.

## Общие метки, история и операторы — миграции 0023–0025

`/api/labels` заменяет отдельный реестр тегов задач. GET возвращает `{id,name,color,kind,revision}[]`, принимает необязательный `kind=tag|category` и синхронизирует прежние метки из задач/привычек, заметок, тренировок, countdowns и зашифрованных контактов. POST принимает `{name,color?,kind?}`, PUT `/labels/{id}` — `{name,color?,revision}`, DELETE — `{revision}`. Названия длиной 1–64 символа, до 30 меток в записи, совпадение без учёта регистра в пределах пользователя и вида метки. Реестр хранит шифротекст имени/цвета и HMAC-ключ сравнения, привязанный к пользователю и виду; контактные метки не появляются открытым текстом в общей таблице. Старые `/task-tags` маршруты остаются алиасами того же владельца, GET возвращает только теги. Старый реестр импортируется с сохранением ID/цветов при первом чтении и очищается после успешного импорта.

Переименование/удаление тегов обновляет задачи, заметки, тренировки, countdowns и приватные контакты внутри одной транзакции; исторические снимки сохраняются. ID категории стабилен при переименовании. Удаление пользовательской категории переключает связанные countdowns на `other`. Категория countdown теперь проверяется как enum `birthday|anniversary|holiday|personal|work|other` или существующий `custom:<uuid>` того же владельца. Прежние русские системные значения принимаются для совместимости и нормализуются; произвольные старые категории миграция сохраняет как теги. Countdown принимает и возвращает `tags`.

`DELETE /api/history/{kind}/{key}` убирает запись из истории пользователя с проверкой владения. Виды: `task`, `habit` (ключ `uuid:YYYY-MM-DD`), `pomodoro`, `workout`, `ai`, `activity` (ключ UUID). Для сессий разрешены только конечные состояния. Общая таблица `history_removals` задаёт исключение из соответствующих журналов; operational results и записи идемпотентности AI сохраняются. Операция повторяема. Этот контракт не является удалением результатов из статистики и не заменяет отдельное удаление аналитики привычки.

`GET /api/operators/settings` возвращает только `{enabled,configured}`. PUT принимает `{enabled,api_key?,remove_key?}`, шифрует ключ с привязкой к владельцу и очищает его кеш. `POST /api/operators/lookup {phone}` принимает нормализованный российский мобильный E.164 и возвращает `{operator,source,checked_at,ported}` или `null`. Номер не передаётся в URL браузера; сервер обращается к фиксированному HTTPS endpoint num7. Ограничения: таймаут 4 секунды, без перенаправлений, ответ до 16 КиБ. HMAC-ключ кеша привязан к владельцу; содержимое зашифровано. Advisory lock объединяет параллельные проверки одного номера. TTL результата — 24 часа, отсутствия результата — час. При отсутствии настройки возвращается `null`; ошибки провайдера не раскрывают номер/ключ и обрабатываются frontend как повод использовать локальный архивный диапазон. Без пользовательского ключа настоящая проверка MNP не выполнялась.
