# Для чего я делую эти улучшения
Я хочу расширить функциональность LifeCycle, сделать приложение более гибким, информативным и удобным для повседневного использования, планирования, самоанализа и отслеживания различных событий жизни человека.

Улучшения затрагивают шесть основных систем: обратный отсчёт, аналитику, Pomodoro, профиль пользователя, управление задачами и интеграцию между модулями.

# Цель данного проектирования

Разработать согласованное расширение LifeCycle, в котором пользователь получает гибкие инструменты управления временем, событиями, задачами, продуктивностью и собственной жизненной историей.

Система должна оставаться удобной при минимальном заполнении данных, но предоставлять расширенные возможности тем, кто хочет глубоко настраивать приложение и анализировать свою жизнь.

Главный принцип: максимальная функциональная гибкость для пользователя при минимальном дублировании данных, предсказуемом поведении, сохранении существующей работоспособности и возможности дальнейшего расширения архитектуры.

# Контактная книжка (Contacts)

Создать самостоятельный модуль управления контактами.

**Функциональность:**

- Создание, редактирование и удаление контактов.
- Хранение имени, фамилии, отчества.
- Хранение нескольких телефонных номеров.
- Хранение даты рождения.
- Хранение описания контакта.
- Указание отношений с пользователем.
- Указание профессии и рода деятельности.
- Пользовательские категории контактов.
- Теги для организации контактов.
- Поиск, сортировка и фильтрация.
- Импорт контактов из адресной книги устройства.
- Обновление импортированных контактов.
- Предотвращение дублирования.
- Связь с событиями обратного отсчёта.
- Автоматическое создание событий дней рождения.
- Управление связями без удаления исходных контактов.
- Возможность ручного создания контактов без импорта.

**Конфиденциальность:**

- Контактная книжка полностью закрыта для AI.
- AI не должен иметь прямого или косвенного доступа к контактам.
- Содержимое контактов не должно попадать в контекст AI, embeddings, поисковые индексы AI, промпты или журналы AI-запросов.
- AI не должен иметь возможность вызывать операции чтения контактной книжки.
- Сведения контактов не должны автоматически передаваться внешним AI-провайдерам.
- Данные должны быть защищены при хранении и передаче.
- Доступ разрешён только владельцу контактов через авторизованные интерфейсы приложения.
- Экспорт, удаление и синхронизация должны контролироваться пользователем.

**Взаимодействие с Countdown:**

Контактная книжка является основным источником данных контакта. Countdown хранит ссылку на контакт и параметры события, не создавая лишних копий ФИО, телефона и других сведений.

При изменении даты рождения связанное событие обновляется автоматически.

При удалении контакта пользователь выбирает, сохранить ли событие как самостоятельное или удалить связь и событие.

**Особое правило:**

Генератор AI-поздравлений не получает доступ к контактной книжке. Для AI пользователь самостоятельно вводит разрешённые сведения в отдельную форму генерации. Шаблонные поздравления могут формироваться локально без обращения к AI.

### 3. Pomodoro

Превратить фиксированный Pomodoro-таймер в конструктор пользовательских алгоритмов работы и отдыха.

**Базовая модель:**
- `w` — Work, рабочий интервал.
- `c` — Chill, обычный отдых.
- `mc` — More Chill, продолжительный отдых.

**Настройка:**
- Пользователь самостоятельно задаёт продолжительность каждого типа интервала.
- Пользователь создаёт собственные последовательности интервалов.
- Поддерживаются повторение всей последовательности и однократное выполнение.
- Пользователь может сохранять несколько независимых конфигураций.
- Каждой конфигурации назначается собственное название.
- Предусмотреть редактирование, копирование, удаление и выбор сохранённой конфигурации.
- Предоставить визуальный конструктор, позволяющий добавлять, удалять и переставлять интервалы.

**Пример алгоритма:**

`w → c → w → c → w → mc → w → c → w → c → w → mc → ...`

**Работа таймера:**
- Отображать текущий этап, оставшееся время и следующий этап.
- Поддерживать запуск, паузу, продолжение, остановку и сброс.
- Корректно переключать этапы и повторять заданную последовательность.
- Предусмотреть уведомления о смене этапа.
- Сохранять историю завершённых рабочих сессий для дальнейшей аналитики.
- Корректно восстанавливать состояние при сворачивании приложения и перезапуске, учитывая ограничения операционной системы.

### 7. AI-помощник (AI Assistant)

Исправить управление привязками AI-провайдеров.

### Проблема 1. Невозможно удалить предыдущий вход через ChatGPT

**Существующее поведение:**

После входа через ChatGPT с использованием провайдера OpenAI пользователь может выполнить вход повторно, но не может полностью удалить сохранённое подключение.

**Требуемое поведение:**

- Отображать список сохранённых подключений.
- Позволять отключить активное подключение.
- Позволять полностью удалить выбранное подключение из LifeCycle.
- Удалять локальные токены, секреты и метаданные подключения, которые больше не нужны.
- Удалять соответствующие учётные данные на сервере.
- Сбрасывать состояние привязки в интерфейсе.
- Очищать связанные с подключением временные данные.
- Предлагать повторное подключение при необходимости.

**Решение:**

Разделить три действия:

1. **Отключить** — временно запретить использование подключения.
2. **Отвязать** — удалить подключение из LifeCycle и связанные сохранённые учётные данные.
3. **Отозвать доступ у провайдера** — выполнить отзыв авторизации через поддерживаемый провайдером механизм либо объяснить пользователю, как сделать это в настройках провайдера.

Не утверждать, что доступ отозван у OpenAI, если фактически удалена только локальная привязка.

**Дополнительные требования:**

- Явное подтверждение отвязки.
- Корректная обработка ошибок.
- Отсутствие повторного использования удалённых токенов.
- Проверка состояния после перезапуска.
- Повторная авторизация по инициативе пользователя.
- Отвязка AI не должна удалять основной аккаунт LifeCycle.

## 8 Заметки (Notes)

Добавить систему управления доступом AI к содержимому заметок.

**Типы доступа:**

- `private` — закрытая заметка, недоступная AI.
- `ai_shared` — заметка, явно разрешённая для использования AI.

**Функциональность:**

- Переключатель «Разрешить доступ AI».
- По умолчанию все новые заметки закрыты.
- Возможность изменить статус доступа в любое время.
- Визуальное обозначение доступных AI заметок.
- Фильтрация по статусу доступа.
- Поддержка массового изменения статуса с подтверждением.

**Правила безопасности:**

- AI получает только заметки с действующим разрешением.
- Разрешение контролируется сервером.
- Клиент не должен самостоятельно обходить ограничения.
- Закрытые заметки не включаются в AI-поиск, контекст или embeddings.
- После отзыва доступа связанные поисковые индексы и кеши должны быть очищены или исключены из использования.
- Ранее переданные внешнему провайдеру данные не могут гарантированно удаляться одним переключателем: пользователь должен быть предупреждён об этом.
- Передача разрешённой заметки внешнему провайдеру должна соответствовать явно выбранному сценарию использования.
- Системные инструкции AI не должны иметь возможность менять статус разрешений
