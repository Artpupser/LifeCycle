# Интеграции и видеоигры

Единый реестр `shared/integrations.json` используется сервером и блоком «Интеграции» профиля. Steam и Epic Games зарегистрированы как игровые адаптеры. Существующие AI и num7 доступны через этот же блок и сохраняют прежние владельцы настроек, разрешений и секретов.

## Steam

В профиле откройте «Интеграции», подтвердите аккаунт на сайте Steam, сохраните собственный Steam Web API key и запустите синхронизацию. В Steam должны быть доступны данные об играх. Пароль Steam приложение не запрашивает. Настройки аккаунта и ключ шифруются общим DataCipher; API возвращает только признак сохранённого ключа. Библиотека и игровое время тоже хранятся зашифрованно.

OpenID проверяет endpoint, подпись через Steam, signed fields, return_to, индивидуальный SteamID, срок nonce, одноразовый state и исходную сессию. Конкурирующие изменения защищены ревизией и идентификатором экземпляра подключения. Отключение удаляет ключ, снимок библиотеки и незавершённые попытки привязки. Снимок от старого подключения не может записаться после отключения и повторной привязки.

Синхронизация Steam получает библиотеку, общее игровое время, время за последние две недели и последний запуск. Закрытая библиотека не интерпретируется как пустая. Недоступное время за две недели остаётся неизвестным. Фон обновляет активные подключения раз в шесть часов; ручные запросы ограничены и дедуплицируются. Неудачная синхронизация сохраняет последний успешный снимок.

## Предложения и уведомления

Серверные адаптеры GamerPower и CheapShark загружают раздачи полных игр и предложения Steam. Каталог обновляется фоном каждые 15 минут, ручная проверка использует общий серверный кеш не менее пяти минут. Скидка вычисляется из точных денежных строк: бесплатная цена либо строго больше 90%, без включения ровно 90%. CheapShark используется для обнаружения предложений; цены Steam повторно запрашиваются одним пакетным запросом appdetails с cc из страны проживания профиля. Сохраняется фактическая валюта площадки; скидка региона проверяется повторно. Wire scale appdetails — сотые единицы для всех валют, независимо от ISO (публичные ответы Portal: JPY 140000 → ¥1400; KWD 250 → 2.50 KD). CLDR описывает доступные валюты и дробные разряды для отображения/иконок, но не меняет масштаб сырых сумм Steam. При отсутствии страны, недоступности цены/региона или источника цена другого региона не подставляется. Нативный каталог Epic запрашивается для той же страны. Окончательные условия определяются регионом игрового аккаунта. Устаревшие данные отмечаются в интерфейсе. Игры не покупаются и не добавляются в аккаунт автоматически.

Статус владения подтверждается только совпадением идентификаторов игры и площадки с последней успешной библиотекой. Неизвестный статус отличается от отсутствия. Для недоступных библиотек других площадок доступна отдельная ручная отметка; она не выдаётся за подтверждение площадки. Игры с подтверждённым владением остаются в списке предложений.

Первая подписка запоминает исходный каталог каждого источника без рассылки прежних раздач. Фон сохраняет новые уведомления с дедупликацией; они доставляются через существующий FeedbackProvider при открытом приложении и остаются непрочитанными до показа/закрытия. Браузерное уведомление отправляется только при уже выданном разрешении. Доставка при полностью закрытом браузере через push/email не реализована. Выключение доступно в общем меню списка предложений. Сбой одного источника не останавливает уведомления другого.

## Распродажи и календарь

Steam адаптер разбирает актуальные Seasonal Sales официальной страницы upcoming_events и автоматически обнаруживает новые годы/сезоны; даты TBD не создают события. Дата без объявленного времени остаётся событием на весь день в часовом поясе пользователя. Нативный freeGamesPromotions Epic предоставляет текущие и будущие окна раздач: они отмечаются как раздачи, отдельно от сезонных распродаж. Необъявленные общие сезонные распродажи Epic не выдумываются. Перечень игровых адаптеров берётся из реестра интеграций; отсутствие данных площадки явно отмечается. `shared/game-sales.json` — только исходный резерв при недоступном Steam, с датой проверки и отметкой устаревания. Обнаруженные акции добавляются в существующие отсчёты двумя событиями — начало и окончание. Импорт переиспользует валидацию и сохранение countdowns. Идентификатор события стабилен для владельца, источника и границы распродажи; повторное добавление не создаёт копии. Созданные события отображаются прежними проекциями Today/Calendar и редактируются обычным редактором событий. Необъявленные даты не экстраполируются.

## Новые площадки

1. Добавьте описание площадки и доверенные домены в `shared/game-platforms.json`; его используют предложения, поиск и владелец внешних ссылок/иконок.
2. Зарегистрируйте интеграцию, её capabilities и разрешённый адрес авторизации в `shared/integrations.json`.
3. Реализуйте серверный адаптер авторизации и получения `integrations::Game`/`Snapshot`. Секреты и снимки остаются в прежнем владельце integrations, с привязкой к пользователю и экземпляру подключения. Общий формат уже агрегирует данные разных поставщиков; отдельную базу людей/игр или клиентский кеш создавать не нужно.
4. При необходимости расширьте серверный адаптер предложений и каталог объявленных распродаж. События импортируйте через countdowns, уведомления — через shared::feedback. Доступность API и права на библиотеку проверяются для каждой площадки отдельно.

## Ошибки и ограничение запросов

Список добавленных распродаж запрашивается через владельца countdowns по существующим событиям; удаление событий физическое, архивная колонка не используется. Повторный импорт сохраняет уже существующие события и создаёт только отсутствующие.

Общий frontend API и кеш приостанавливают обращения после временных ошибок: 30, 60, 120, 240 и 300 секунд при последовательных сбоях. HTTP 429 даёт минимум пять минут с дальнейшим увеличением задержки. Числовой Retry-After и HTTP-дата соблюдаются, даже если сервер прислал HTML вместо JSON. Фокус, предзагрузка, ручной повтор и операции раздела используют общую паузу; успешные сохранённые данные остаются видимыми. В localStorage сохраняются только публичные названия разделов и метаданные паузы, чтобы перезагрузка не обходила ограничение. После подтверждённого успешного ответа счётчик сбрасывается. Автоматических повторов изменяющих запросов нет.

Backend сохраняет failure_count/retry_at в прежних записях интеграций и источников. После ошибки внешнего сервиса пауза начинается с пяти минут и растёт до часа; более длинный Retry-After сохраняется. Источники независимы. Во время паузы ручной refresh и фоновая задача не обращаются к приостановленному источнику и не продлевают его срок без нового реального сбоя.

## Epic Games

По выбору пользователя используется вход через браузер Epic с одноразовым authorizationCode, совместимый с протоколом лаунчера (как Legendary). Собственные Client ID/Secret больше не требуются. В профиле нажмите «Подключить Epic Games», откройте ссылку входа Epic, вставьте код или JSON с authorizationCode и подтвердите. Пароль вводится только на Epic. Это неофициальный API; Epic может изменить его или отозвать сессию.

Начало входа создаёт одноразовый state на 10 минут с привязкой к владельцу, исходной сессии LifeCycle, экземпляру подключения и ревизии. Код передаётся POST body, не сохраняется в истории/локальном хранилище и обменивается сервером один раз. Конкурирующие обмены/синхронизации сериализуются прежним owner lock. Сессия access/refresh хранится прежним DataCipher; браузер получает только статус, имя аккаунта и время синхронизации. Смена Epic-аккаунта очищает снимок прежнего аккаунта; CAS предотвращает возврат данных после отключения или изменения настроек. Старые OAuth-настройки остаются удаляемыми, при входе кодом заменяются новой сессией.

Ввод и подтверждение кода не запускают первую синхронизацию. После подключения пользователь отдельно нажимает «Синхронизировать библиотеку». Только после первой успешной загрузки фон может обновлять Epic раз в шесть часов. Адаптер читает библиотеку с пагинацией, без запросов метаданных для каждой игры; поток ограничен по объёму/времени и останавливается при ошибке или 429. Неизвестная схема/незавершённые страницы не заменяют последний полный снимок. Обновлённый refresh token сохраняется и при последующем сбое загрузки библиотеки, если конфигурация не изменилась.

Идентификатор игры включает namespace и catalogItemId. Владение предложением подтверждается по точным namespace/item из нативного каталога Epic; совпадения названий не используются. Движок/известные приватные/DLC-записи исключаются. Название и превью берутся из метаданных ответа; при отсутствии названия виден доступный идентификатор, при отсутствии картинки — существующее состояние media. Полное игровое время, недавнее время и последний запуск Epic в этом адаптере неизвестны: в JSON null, в интерфейсе «Недоступно»/тире. Суммарная статистика времени не выдаёт неполные данные разных площадок за полный итог.

Долгий sync остаётся задачей существующего integrations owner: POST возвращает результат либо 202/pending через семь секунд; сама ограниченная задача продолжает работу. Профиль/Игры обновляют метаданные через useResource раз в 15 секунд только при syncing; завершение обновляет каталог. Отдельного владельца задач/планировщика нет.

Источники протокола: [Legendary EGS adapter](https://github.com/legendary-gl/legendary/blob/master/legendary/api/egs.py), [Legendary CLI](https://github.com/legendary-gl/legendary/blob/master/legendary/cli.py). Legendary не устанавливается и его код не включается в сборку; реализован собственный Rust-адаптер протокола в прежнем owner. Официальный EAS/Ecom имеет иной набор разрешений и не используется как подтверждение доступности библиотеки лаунчера.

## Изображения и быстрые фильтры

Превью предложений и библиотеки проходят через прежнего владельца media: доверенные CDN, HTTPS без редиректов, проверка MIME/сигнатуры и лимита 8 МБ, ленивое сохранение в приватное S3-хранилище и загрузка через UserImage. Браузер не обращается к CDN площадок. Привязка доступна только владельцу; ошибки CDN ставят увеличивающуюся паузу по хосту. Реестр разрешённых CDN находится в media, новые площадки расширяют его.

FilterSearch во всех существующих местах использует общий ObjectActions: кнопка в поле, правая кнопка мыши и Shift+F10. FilterSpec.choices объявляет быстрые значения с иконками; при отсутствии choices используются values/пример. Выбор заменяет положительный фильтр и его алиасы, сохраняя свободный текст, кавычки, остальные условия и исключения. Другие поля сохраняют нативное контекстное меню. Игры объявляют площадки через прежний game-platforms; валюты доступны через pack:currencies/набор:валюты в общем IconPicker.

Миграция 0040 расширяет прежний game_feeds типом данных, добавляет привязку приватных provider media и ревизию попытки OAuth. Метаданные цен/акций не смешиваются со списками предложений. Пауза адаптера общая для регионов, защищена advisory lock и сохраняется между рестартами. Самостоятельных централизованных систем в этой правке нет: расширены integrations, videogames/cache, media, icons, search/actions и countdowns.

## Проверки этой правки

Целевой ESLint, TypeScript/Vite production build, 14 frontend unit и 15 backend проверок выполнены успешно. PostgreSQL изолирована временным контейнером; проверены миграции, региональная цена RUB/бесплатная цена, приватность provider media, настройка Epic и session-bound state, повторный импорт календаря и сохранение пауз. Все 7 Chromium сценариев прошли (быстрый фильтр повторён после исправления названия площадки в тесте). Изменённый порядок валютных иконок проверен отдельно, frontend пересобран.

При последней сверке официальных ответов appdetails уточнён wire scale JPY/KWD: всегда raw/100. Фикстуры этих двух примеров скорректированы, но unit-тесты после последнего уточнения не перезапускались в рамках лимита трёх блоков проверки; итоговый backend образ успешно собран. Реальный Epic OAuth с пользовательским аккаунтом не выполнялся. Локальные контейнеры обновлены, существующие тома сохранены; штатный readiness через frontend вернул 200 (PostgreSQL/Redis/Garage ok). Graphify query/update недоступны: CLI отсутствует.

## Независимые паузы интеграций

Общий API/retry учитывает метод и операцию интеграции: чтение списка, настройки, отключение и внешние действия разделены по публичному ID площадки. connect/authorize/sync одной площадки сохраняют общую паузу, другие площадки и локальные настройки доступны. Настоящий общий gateway 429 сохраняет блокировку приложения. Старая запись /integrations в localStorage автоматически переносится на внешние операции, без потери сохранённого дедлайна. Сохраняются только публичные названия операций и временные метаданные.

Настройки и отключение не выполняют синхронизацию; успешное сохранение не отменяет текущую паузу площадки. Черновик формы не сбрасывается при неудачном запросе/обновлении метаданных. Прежний save_key допускает локальное исправление даже при retry_at в будущем и сохраняет дедлайн внешнего сервиса.

## Проверки входа кодом и исправления пауз

Целевые lint/TypeScript/Vite и компиляция backend выполнены успешно. 15 frontend unit и 17 backend проверок прошли; использованы временная PostgreSQL и локальный mock Epic, без реального аккаунта. Проверены перенос старой блокировки, независимость операций/площадок, общий gateway 429, state чужой сессии, одноразовое погашение кода, отсутствие токенов в API, локальное исправление конфигурации во время provider pause, refresh rotation и пагинация/429. Ранее уточнённый Steam wire scale JPY/KWD также прошёл в затронутом модуле.

Из шести Chromium сценариев пять прошли: новый Epic-вход, отсутствие sync при вводе/подтверждении кода, отдельная синхронизация и её статус, редактирование Steam после ошибки Epic, перенос старой паузы и отключение, сохранение общих ограничений. Сценарий профиля обнаружил переполнение кнопки на ширине 320px: возвращены прежние max-width/перенос. После этой CSS-правки production frontend пересобран, но E2E не повторён в рамках DEEP-лимита; одна попытка запуска runner завершилась до выполнения тестов. Backend/frontend обновлены локально с сохранением томов. Реальная авторизация Epic не проверялась чужими кодами/паролями: пользователь завершает вход на сайте Epic и в профиле LifeCycle.
