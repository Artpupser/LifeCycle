## Главное правило
Поведение должно остаться прежним. Не меняй семантику, коды ошибок, формат JSON и SQL-результаты. Если считаешь, что поведение нужно изменить (баг, гонка, уязвимость), не меняй молча: вынеси это в отдельный раздел «Найденные проблемы».

## Что улучшать
1. Типобезопасность: строки-«enum-ы» заменить на enum с serde/sqlx-derive, примитивы с доменным смыслом на newtype, невозможные состояния сделать непредставимыми.
2. Структура: разбить большие функции и модули по ответственности (handlers / repository / domain / dto), без god-модулей.
3. Дублирование: вынести повторяющийся код, SQL и магические числа в функции и константы с говорящими именами.
4. Идиоматичность: итераторы вместо ручных циклов, `?` и `let-else` вместо вложенных match, `From`/`TryFrom`/`FromStr` вместо ad-hoc конверсий, корректные `&str`/`&[T]` в параметрах, минимум `clone()`.
5. Ошибки: никаких `unwrap`/`expect` вне тестов, ошибки с контекстом, внутренние причины логировать, а не терять.
6. Производительность: лишние аллокации, N+1 запросы, загрузка лишних данных, `SELECT *`. Предлагай только то, что можно обосновать.
7. Читаемость: понятные имена (без `s`, `u`, `v`)
8. Форматирование: код должен проходить `cargo fmt`, `cargo clippy -- -D warnings`.
