### Найденные проблемы и границы сохранения поведения

- Основной рефакторинг сохраняет маршруты, JSON, тексты и порядок валидационных ошибок, статусы, сортировки SQL, блокировки, транзакции и шифрованные контексты. Сырой текст входных команд сохраняется в DTO и преобразуется в доменный enum на прежнем этапе обработки: перенос разбора в serde изменил бы приоритет и сообщения ошибок.
- Отдельное изменение для повреждённых данных: программная Pomodoro-сессия без interval_index раньше вызывала panic через unwrap; теперь возвращает прежнюю общую ошибку internal_error/HTTP 500 с серверной диагностикой. Штатные пути создания программы всегда записывают индекс; схема БД не менялась. Это исключение из строгого равенства поведения ошибочных вручную изменённых записей выделено явно.
- Удалённые из Contacts/Countdowns unwrap календарных дат заменены проверяемым построением; валидные календарные аргументы и ограничения SQL сохраняют прежние результаты. В новых модулях нет unwrap/expect или комментариев.

### Найденные баги, которые намеренно не менялись

- Одиночный Pomodoro принимает reset в списке допустимых действий маршрута, но обработчик одиночной сессии не имеет такой ветки и возвращает HTTP 409. Reset программы работает и проверен существующим smoke. Изменение одиночного таймера потребовало бы нового пользовательского поведения.
- habits::summarize предполагает наличие schedule/habit и корректный timezone внутри сохранённого снимка: при повреждённом JSON возможен panic через существующие unwrap. Program::wall также предполагает непустой anchors, Program::position — корректную последовательность и положительные длительности. Эти существующие пути не переводились молча в пропуск записей, нулевую статистику или новые API-ошибки. Глобальное удаление всех unwrap из оставшегося backend не заявляется.
- Чтение одного отсчёта по-прежнему загружает согласованный список и связанные контакты. Переход на отдельный SELECT изменил бы поведение при повреждённых посторонних записях; такой пересмотр не включён в текущие изменения.
