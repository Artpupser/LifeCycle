## Принятые решения

- Отдельные проекты `backend/` и `frontend/`, общий Compose. Backend — единственный источник сохраняемых данных.
- Axum и SQLx для HTTP API и миграций PostgreSQL; Redis для будущих временных кодов, ограничений и сессий.
- Browser использует относительный `/api`, Vite и nginx проксируют его на backend; cross-origin API пока не требуется.
- Garage запускается как один узел для локальной разработки; bucket приватный, ключи генерируются локально. Этот режим не обеспечивает резервирование данных.
- Для будущих этапов: IANA timezone профиля, общая backend-модель расписания, UTC для конкретных моментов; идемпотентные появления Today; версионирование правил и snapshots результатов вместо каскадного удаления истории.
- Countdown и Pomodoro включены в этап 3, поскольку они обязательны в пользовательских требованиях, хотя не перечислены в кратком названии этапа.
- SMTP-песочница допустима для проверки реальной доставки локальной почты; AI без настоящего ключа не считается проверенным внешним сервисом.
- Данные профиля и интимного журнала не передаются AI без явного разрешения. Медицинские утверждения из описания не используются как установленные факты продукта.
- Расписания: ISO-дни недели 1–7, даты окончания включительно, интервалы считаются календарными днями. При повторяющемся времени DST выбирается первый момент, при отсутствующем — ближайшая допустимая минута (включая перенос пропущенного календарного дня). Для запросов расписания диапазон ограничен 366 датами. События без времени остаются задачами на день.
- Продолжительность одного планового занятия — 1–1440 минут; повтор каждые N дней — 1–3650 дней. Более длинные проекты разбиваются на занятия/подзадачи. Выполнение повторяющейся задачи сохраняется отдельно для каждой даты.
- Для ежегодных countdown дата 29 февраля в невисокосном году соответствует 28 февраля.
- Даты timed-событий в Today/календаре и поиске вычисляются в часовом поясе профиля по UTC `starts_at`. `TaskOccurrence.date` остаётся ключом повторения в часовом поясе расписания и используется при отправке отметки. События без времени привязаны к календарной дате.
- Завершённые и отклонённые появления хранят snapshot названия, описания и времени. Незавершённые отметки используют актуальный шаблон; удаление шаблона (с этапа 7) прекращает генерацию будущих появлений и сохраняет результаты. Вычисляемое API-поле `editable` отключает изменение исторических отметок удалённых объектов и дат вне актуального правила; capability не сохраняется внутри snapshots.
- Pomodoro хранит активную сессию и время на сервере, допускает паузу/продолжение и восстановление после перезагрузки. Завершение интервала подтверждается после истечения серверного времени и не меняет статус связанной задачи автоматически. Звуковые и push-напоминания относятся к последующим этапам.
